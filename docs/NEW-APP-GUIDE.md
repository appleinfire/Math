# Как сделать новое приложение на той же оболочке

Оболочка Math Expedition вынесена в отдельный проверенный шаблон: **[`templates/app-shell/`](../templates/app-shell/)**. В нём нет математики — только то, что нужно любому семейному приложению:

| Что | Как работает |
|---|---|
| **Профили** | «Who's playing?» — карточки детей; форма нового профиля (имя, группа — класс/возраст, картинка); если профиль один, приложение сразу открывает его. У каждого профиля свой прогресс. |
| **Прогресс на всех устройствах** | На первом устройстве *Create a family* (код семьи + PIN), на остальных *I already have a family*. Firebase (Firestore + анонимный вход, бесплатный план). PIN никуда не отправляется: из кода и PIN браузер делает длинный ключ. Каждое устройство хранит полную копию, работает без интернета, а копии, сыгранные офлайн на двух устройствах, сливаются без потери заработанного. |
| **Раздел для взрослых** | За вопросом на умножение: отчёт (показатели, активность за 14 дней), настройки, переименование, статус синхронизации и отключение устройства, код сохранения (резервная копия или перенос без облака), список профилей (сменить группу, удалить со второго нажатия), сброс прогресса (старая копия на другом устройстве его не вернёт). |
| **Просмотр для взрослых** | Всё открыто на копии профиля, ничего не сохраняется, сверху фиолетовая полоса с кнопкой Exit. |
| **Навигация** | Кнопка «назад» на каждом экране; жест «назад» в браузере переходит между экранами и спрашивает перед выходом из игры. |
| **Установка и офлайн** | PWA: на iPad Safari → Поделиться → На экран «Домой»; работает без интернета. |
| **Публикация** | Каждый push в `main` запускает тесты и публикует сайт на GitHub Pages примерно за минуту. |

Шаблон проверен тремя тестами: `tests/shell.test.js` (слияние копий, хранение, просмотр, код сохранения, ключ семьи), `tests/smoke.mjs` (два профиля, игра, вход для взрослых, просмотр, жест «назад», перезагрузка в Chromium) и `tests/cloud-e2e.mjs` (два «устройства» синхронизируются через настоящий Firebase).

## Шаги

**1. Шаблон должен быть в `main` этого репозитория.** Пока он лежит в ветке `claude/peaceful-darwin-1h8tn2`: слейте её в `main` (через pull request). Новый чат будет брать файлы из `appleinfire/Math`, ветка `main`.

**2. Создайте новый репозиторий на GitHub.** github.com → New repository, например `appleinfire/Reading`:
- **Public** (GitHub Pages бесплатен только для публичных репозиториев; в коде нет секретов);
- поставьте галочку *Add a README file*, чтобы сразу появилась ветка `main`.

**3. Включите GitHub Pages:** в новом репозитории Settings → Pages → Source: **GitHub Actions**.

**4. Откройте новый чат Claude Code** (claude.ai/code) на новом репозитории и вставьте промпт из раздела ниже, дописав в конце идею приложения.

**5. Опубликуйте.** Claude работает в своей ветке и предложит pull request. Когда вы сливаете его в `main`, GitHub Actions публикует сайт: `https://appleinfire.github.io/<имя-репозитория>/` (ход публикации — вкладка Actions).

**6. Синхронизация между устройствами.** Ничего настраивать не нужно: промпт говорит использовать тот же Firebase-проект, что и у Math Expedition. Его разрешённый домен `appleinfire.github.io` подходит для всех ваших репозиториев, а данные разных приложений не смешиваются (ключ семьи у каждого приложения свой). Общие бесплатные лимиты (50 000 чтений и 20 000 записей в день) для семьи огромны. Если когда-нибудь захотите отдельный Firebase-проект — пошаговая инструкция в `templates/app-shell/README.md`, раздел *Option B*.

> Код семьи и PIN в каждом приложении свои: новое приложение — это новая «семья». Можно взять тот же код и PIN, что и в Math Expedition, — это будет отдельная семья нового приложения.

````text
Мы строим новое приложение для детей на готовой оболочке из моего публичного репозитория
https://github.com/appleinfire/Math — папка templates/app-shell/ (ветка main).
Оболочка уже умеет: профили детей с выбором «кто играет», синхронизацию прогресса между
устройствами через Firebase (код семьи + PIN), раздел для взрослых за вопросом-замком, режим

Эталон полной реализации на этой же оболочке — само приложение Math Expedition в том же
репозитории (js/app.js, js/store.js, README.md).

## Шаг 1. Перенеси оболочку в этот репозиторий
- git clone --depth 1 https://github.com/appleinfire/Math во временную папку (вне рабочего
  каталога). Если клонирование не проходит — подключи репозиторий appleinfire/Math инструментом
  add_repo (доступ на чтение) и клонируй снова.
- Скопируй в корень этого репозитория всё содержимое templates/app-shell/ (включая скрытые
  .github/ и .gitignore) и папку js/vendor/ из корня Math (Firebase SDK 10.14.1).
- Существующий README.md этого репозитория замени README из шаблона, переписав его под
  новое приложение.

## Шаг 2. Настрой под новое приложение
- js/config.js: name, id (короткий, латиница с дефисами, уникальный: НЕ 'math-expedition'
  и не 'my-app'; после запуска не менять), profileWord, kinds (группы профилей: классы или
  возраст), avatars.
- firebase в js/config.js: возьми объект MQ.CLOUD_CONFIG из js/cloud-config.js репозитория
  Math (это общедоступные идентификаторы проекта, не секреты). Ничего в Firebase настраивать
  не нужно: домен appleinfire.github.io уже разрешён, правила firestore.rules уже стоят,
  данные отделены, потому что ключ семьи солится APP.CONFIG.id.
- sw.js: PREFIX = '<id>-cache-'. index.html и manifest.webmanifest: название, описание,
  цвета. icons/: свои иконки (svg + png 180/192/512; png можно сделать из svg Chromium'ом).

## Шаг 3. Построй само приложение
- Свои данные профиля — в js/schema.js: fresh(kind) и mergeProgress(out, nw, old, M).
  Для каждого нового поля реши, как сливаются две копии (сыгранные офлайн на двух
  устройствах): собранное (уровни, награды, предметы) — объединение с лучшим значением;
  растущие счётчики — максимум; то, что тратится или меняется (монеты, настройки) — из более
  новой копии. На каждое правило — проверка в tests/shell.test.js.
- Свои экраны — в js/app.js вместо демо (home, play, next, answer, finish). Держись
  устройства оболочки:
  * экран = функция, которая вызывает render(html); активности — с классом 'is-play'
    (тогда жест «назад» спрашивает перед выходом, а данные с другого устройства не
    перерисовывают экран посреди игры);
  * кнопки — data-act="действие" data-arg="аргумент", обработчики в ACTIONS;
    переход между экранами — go('экран') (добавь экран в таблицу внутри go);
  * экраны, которые только показывают данные, ставят cur = 'имя', и onCloud их
    перерисовывает, когда приходят изменения с другого устройства;
  * после изменения APP.state — APP.store.save() (сохранит локально и отправит в облако);
    в режиме просмотра save ничего не делает — так и должно быть, ничего не награждай в
    просмотре;
  * раздел для взрослых — parent(): добавляй туда отчёты и настройки нового приложения;
    «Unlock everything» должен открывать весь контент;
  * обычные <script> без сборки и без npm-зависимостей, всё через глобальный объект APP;
    каждый новый js/css-файл добавь и в index.html, и в FILES в sw.js (тест это проверяет);
  * текст интерфейса на английском (если ниже не сказано иначе), крупные кнопки,
    удобно на iPad и телефоне.
- Если в приложении есть длинные сессии (тесты), используй APP.store.setPaused /
  paused / clearPaused, чтобы можно было продолжить после перерыва.

## Шаг 4. Проверь
- node tests/shell.test.js, node tests/smoke.mjs (Playwright, Chromium уже установлен),
````

## Если захотите перенести новую функцию оболочки обратно

Оболочка в шаблоне и в Math Expedition устроена одинаково (`MQ` в Math = `APP` в шаблоне, `grade` = `kind`). Улучшение, сделанное в одном приложении (например, новый экран в разделе для взрослых), можно перенести в другое, попросив чат: «перенеси функцию X из appleinfire/Math в этот репозиторий, оболочка та же». А чтобы оно доставалось всем будущим приложениям — попросите обновить и `templates/app-shell/`.
